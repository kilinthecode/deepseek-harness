# Fix boot animation (choppy + cuts fast) and restore "Harness" beside "Portal"

## Root causes (verified in code)

1. **Cuts too fast**: `BootPage.dispose()` already implements the designed brand moment (hold `MIN_HOLD_MS = 1900` from mount, then a 240 ms `.leaving` fade, then remove) — but nothing calls it in the happy path. Instead, `mountApp` in `packages/client/ui-renderer/src/client/index.ts:72-83` hydrates over the boot element and `BootHandoff`'s `useLayoutEffect` swaps in the app in the same commit, whenever plugin boot happens to finish. The animation is cut mid-draw with no fade.
2. **Choppy**: (a) `.letter` transitions `filter: blur(3px)` — non-composited raster work per frame; (b) the spinner arc jumps in hard discrete steps (`--dsh-boot-arc` set to snapped integer degrees, no transition); (c) on desktop the main window is created with `show: true` and a transparent macOS background, so it can appear before the boot page paints.
3. **Missing "Harness"**: this branch changed `OfficialBrandName` to `<PortalWordmark />` alone. The HARNESS plate artwork was extracted into `HarnessNameplate` (`packages/client/ui-primitives/src/HarnessNameplate.tsx`, already exported and unit-tested) but never wired into the sidebar name.

## Changes

### A. Wire the hold + fade into the production handoff

- `packages/client/ui-renderer/src/client/index.ts`: delete `BootHandoff`/`BootSnapshot` and the hydration path. `mountApp` always appends a host `<div style="display: contents">` to the container, `createRoot(host)` + `flushSync` render into it, and returns root + host so the disposer unmounts and removes the host. The kernel's `[data-dsh-boot]` element is left untouched as a sibling.
- `packages/client/web/src/boot-page.module.css`: make `.boot` a top overlay (`position: fixed; inset: 0;` + max z-index with a comment) so it covers the mounted app until it fades; `.leaving` gains `pointer-events: none` so the app is interactive the moment the fade starts; `@media (prefers-reduced-motion: reduce)` drops the leave transition.
- `packages/client/web/src/boot.ts` `run()`: call `this.page.dispose()` right after `await mountClient(...)` — the existing hold/fade/remove sequence now actually runs in production (already idempotent; the failure path never reaches it, so failure reports stay visible).

### B. Smooth the animation

- `boot-page.module.css` `.letter`: remove the `filter: blur(3px)` initial value and its transition (keep opacity + transform — composited, still a clean rise-in).
- `boot-page.module.css`: register `@property --dsh-boot-arc { syntax: '<angle>'; inherits: true; initial-value: 72deg }` and add `transition: --dsh-boot-arc 260ms ease-out` on `.spinner`, so the progress arc sweeps instead of stepping. `inherits: true` is required for the `::after` to see the interpolated value; jsdom tests read the inline style and are unaffected.
- `boot-page.ts`: `MIN_HOLD_MS` 1900 → 2250 so the fade starts after the caret settles (`CARET_FADE_MS = 2150`); update the JSDoc numbers.
- `apps/desktop/src/main.ts` `createMainWindow`: create with `show: false` and `window.once('ready-to-show', () => { if (!window.isDestroyed()) window.show() })` — the exact pattern `update-overlay.ts:33` already uses — so the window first appears with the boot page painted.

### C. Restore "Harness" beside "Portal" (top-left menu)

- `packages/client/ui-brand-official/src/client/Brand.tsx`: `OfficialBrandName` returns `<PortalWordmark />` followed by `<HarnessNameplate />`. The sidebar's `.brandName` (inline-flex, gap 6, height 24) lays them out as `[PORTAL][HARNESS]` right of the mark slot; default nameplate size 24 matches the brand row. Update the JSDoc.

### D. Tests (change obsolete behavior with its tests)

- `packages/client/web/tests/boot-page.client.spec.ts`: dispose test timings 1900 → 2250.
- `packages/client/ui-renderer/tests/ui-renderer.client.spec.tsx`: retitle the "hydrates the boot page" test to the preserved-overlay contract and strengthen it — the same boot node is still `[data-dsh-boot]` after mount and the app probe is present.
- `packages/client/ui-brand-official/tests/browser-plugin.client.spec.tsx`: extend the name test to assert the nameplate svg (`viewBox '129.348 0 52 24'`) renders beside the wordmark; retitle.

### E. Docs (bilingual .md/.zh.md/.i18n.yaml, per docs/AGENTS.md)

- `packages/client/ui-renderer/README.*`: replace the `BootHandoff`/hydration description (summary, `mount` contract, internals) with mount-into-host + kernel-owned fade.
- `packages/client/web/README.*`: update the two-stage boot sentence ("hydrates it and switches to the complete UI" → app mounts beneath the boot page, which holds the brand moment then fades).
- `docs/subsystems/web-client.md` + `.zh.md`: same sentence fix.
- `packages/client/ui-brand-official/README.*`: sidebar name = Portal wordmark + Harness nameplate.
