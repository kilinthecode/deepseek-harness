# Agent Note: Delegation refuses images a child cannot take, before any side effect

Status: implemented

English | [中文](2026-09-23-delegation-refuses-images-before-side-effects.zh.md)

## Problem

[Route-checked image prompts](../feature/2026-09-23-route-checked-image-prompts.md) closed the SDK server and headless entry points, but every delegation path still admitted image content ahead of the check, or skipped the check entirely:

- `TeamMailbox.sendAdmitted` appended `team/message/queued` for any target with no route check; a text-only teammate then died in `assertImageCapable` on the receiving side and stayed queued, with no way to unstick a later text message to the same target. A text-only Lead target skipped that gate entirely, since Lead delivery is a direct `root.steer()` call outside the continuable-child path `assertImageCapable` guards, so the image reached the Lead's own text-only projection instead of refusing.
- `TeamRoster.spawnAdmitted` appended the provisioning `team/member` record before the continuable child was created, so an image-bearing first prompt against a text-only inherited route burned the teammate's name and a member slot on a doomed spawn.
- The Team projection's image Zod schema was stricter than the declared `ImageAttachmentRef`/`ImageBlock` types: a real downscaled reference (`originalDimensions`) or a replayed `offloaded` mark permanently set `state.failure` on the whole Team projection.
- `SubagentContinuationManager.startContinuable` checked image capability only after materializing the child (inside `submitMaterialized`), so a refusal still left a durable child Session behind.
- One-shot `SubagentRuntime.start()` had no image check at all: an image prompt reached ACP, Claude Code, Codex, or the DSH SDK provider, none of which forward image bytes across their process boundary, before any refusal.
- A continuable child's `sendMessage()` call toward its own parent (`sendToParent`) had no image check: a text-only parent received an image message it could not actually use.

## Decision

### Gates live in the operation that decides, before its durable or process side effect

Every delegation path that resolves a provider/model route applies the same check — `imageInputSupport(info) === 'unsupported'` refuses, a missing provider, model, `llm` service, or an undisclosed modality list proceeds — at the point that decides, before the side effect that check exists to prevent:

- `SubagentContinuationManager.startContinuable` checks the resolved child route after capturing delegated policy overrides, holding parent ownership, and calling `prepareContinuable`, and before any child write. The provider's synchronous contribution to `prepareContinuable` (the fork seed) and the delegated policies are both captured before the check's await, the same ordering the one-shot path keeps.
- `SubagentRuntime.start()` checks `provider.imageInput` synchronously, before `provider.start` and before any other await in that call, so it never delays a provider's own pre-first-await work (captured delegated policy, a fork seed read). For an image-capable in-process provider, the resolved-child-route check itself runs in `startInProcessRun` (`packages/subagent/subagent-in-process-driver`), the one driver both `spawn-in-process` and `fork-in-process` share: it runs right after that driver's own synchronous `captureDelegatedPolicyOverrides` capture and before `ctx.agents.create()`, against the same `resolveChildAgentOptions` result the driver passes to `create()`. An awaited route check inside `start()` itself would land between a provider's synchronous pre-first-await captures and its first real await, corrupting exactly the ordering those captures depend on.
- `TeamRoster.spawnAdmitted` checks the inherited child route (the Lead's current delegation route, since spawn requests no per-child override) before the provisioning `team/member` append.
- `TeamMailbox.sendAdmitted` checks the target's route — the live root Agent's current delegation route for the Lead, or `dsh-subagent`'s continuable-child probe for a teammate — before the `team/message/queued` append and outside the journal transaction, so the LLM route lookup never holds the journal lock. The preflight block also repeats the self-message refusal ahead of the route check, so a self-addressed image message reports `TEAM_SELF_MESSAGE` instead of a misleading image refusal.
- `SubagentContinuationManager.sendToParent` checks the live parent Agent's route before `sendWaking`.

The five call sites share one function, `assertImageCapableRoute(ctx, provider, model, signal)` in `packages/subagent/subagent/src/image-capability.ts`, built on `imageInputSupport`. It throws `SubagentError('MODEL_DOES_NOT_SUPPORT_IMAGES')`; the Team mailbox and spawn gates remap the same message to `TeamError('TEAM_IMAGES_UNSUPPORTED')` so the model sees a Team-owned error code.

### `imageInput` is a provider transport fact, not a start-time capability

`SubagentProvider` declares `readonly imageInput: boolean` beside `inheritsParentContext`, not a new row in `SubagentCapabilities`. `SubagentCapabilities` mirrors `SubagentStartRequest` options 1:1; image content is prompt data, not an option the caller opts into. `spawn-in-process` and `fork-in-process` declare `true` (same process, same attachment store). The other four out-of-process providers each declare `false` for a distinct reason, not one shared out-of-process rationale: ACP's prompt mapping carries no image blocks at all — `toAcpPrompt` maps content to text-only ACP prompt parts and has no case for an image block. The DSH SDK provider's child process has its own attachment store, and byte encoding across that boundary is deferred. Claude Code and Codex each map the task to a text-only CLI prompt, and `textTask` throws on any non-text block before the child process starts.

### The Team route probe stays off the public Service Definition

`TeamMailbox` needs a teammate's resolved LLM route — the live Activation's Agent options, or else the persisted descriptor's `agentProvider`/`agentModel` — the same sources cold resume already reads. The fallback is per source: a source that names either field is the route as a whole, and only a source that names neither falls back to the parent's current delegation route as a whole, so the probe never pairs a child's provider with the parent's model. `assertContinuableChildAcceptsImages(runtime, parent, childId, signal)` in `packages/subagent/subagent/src/internal.ts` calls the runtime's private `requireContinuations()` through typed bracket-property access rather than adding a public `SubagentRuntime` method for this one Team caller; `SubagentContinuationManager.resolveChildRoute` and `.assertChildAcceptsImages` stay package-internal methods on a class the public API never exports. Its refusal is constructed by that live `runtime`'s own bundled continuation manager, so it carries the bundled runtime entry's `SubagentError` class — a different identity from the one `internal.ts`'s unchanged re-export of `assertImageCapableRoute` constructs when a caller reached through this `/internal` subpath calls that function directly, as `assertTeamRouteAcceptsImages` (the Lead-target path) does. Both refusals carry the same `error.code` (`MODEL_DOES_NOT_SUPPORT_IMAGES`) and both extend `dsh-llm`'s `HarnessError`, one shared class identity neither bundled nor unbundled `dsh-subagent` duplicates. The Team remap in `packages/experimental/agent-team/src/image-content.ts` therefore guards on `instanceof HarnessError` and matches the specific refusal by `error.code`, never `instanceof SubagentError`: no caller reached through this subpath, teammate or Lead target alike, may rely on that class's identity.

### Team's route check delegates to the subagent-owned gate

`packages/experimental/agent-team/src/image-content.ts` does not reimplement the permissive image-capability policy. `assertTeamRouteAcceptsImages` calls `assertImageCapableRoute` (re-exported from `@deepseek-ai/dsh-subagent/internal`) and remaps its refusal to `TeamError('TEAM_IMAGES_UNSUPPORTED')` by matching `error.code`; `assertTeamTargetAcceptsImages` routes the Lead case through that same function and the teammate case through `assertContinuableChildAcceptsImages`, so one subagent-owned check backs both delegation surfaces and a later policy change cannot silently diverge between them.

### Team admission strips `offloaded`, keeps `originalDimensions`

`packages/experimental/agent-team/src/image-content.ts` clones content bound for a Team mailbox message or spawn prompt and removes `offloaded` from every image block, because offload is a per-target compaction decision the receiver makes about its own request history; a sender's or a replayed copy's mark must not travel with content admitted into a different Session's log. `originalDimensions` is durable ref metadata and is kept. The Team projection's `imageAttachmentSchema` accepts an optional `.strict()` `originalDimensions` object and the image block schema an optional `offloaded: z.literal(true)`, so a real (possibly downscaled) reference or a replayed `offloaded` mark round-trips instead of poisoning the whole Team projection. Event and state versions are unchanged; `verify-persistence-changes` reports no change because both fields are already declared on `ImageAttachmentRef`/`ImageBlock`.

## Alternatives considered

**`textOnlyTargetImages: 'refuse' | 'placeholder'` Team config.** No current consumer needs a placeholder policy, and rewriting a sender's logged blocks into a placeholder diverges the durable record from what the sender actually sent.

**A durable `team/message/rejected` event.** Unneeded once unsupported content never queues; it would add a new `SessionEventMap` root requiring a same-version acknowledgement and both SDKs' expected-output updates for no behavior the refusal path doesn't already provide through the tool-result error.

**Leaving the Team image Zod schema unchanged and only stripping at write.** `originalDimensions` still poisons the projection on any real downscaled reference, since normalization sets it whenever the image was resized; the schema had to widen regardless of where stripping happens.

**A required `SubagentCapabilities.imageInput` row instead of a `SubagentProvider` field.** Capabilities mirror `SubagentStartRequest` options one-to-one; image content is prompt data delegated through every path (one-shot, continuable creation, follow-up delivery), not a start option a caller requests.

**A public `SubagentRuntime.assertChildAcceptsImages()` method for the Team mailbox.** One external caller does not justify widening the Service Definition; the private-continuation-manager read keeps the public surface unchanged while still giving Team the exact sources cold resume uses.

**Folding `SubagentContinuationManager.assertImageCapable` into its call site.** The private method already delegates to `assertImageCapableRoute`, so every delegation path shares one policy definition; folding it would change only the call-site form.

**Widening the `subagent`/`send_message`/`spawn_teammate` tool schemas with an `images` parameter.** That is image travel into delegation — letting a model attach an image to a child prompt — a decision separate from refusing content a child cannot take. The delegation tools carry an optional `images` parameter and pass the resolved image blocks into the same gated operations, so the gates hold for whichever caller supplies the image; this note owns only the refuse-before-side-effect decision.

## Consequences

A Team teammate inherits the Lead's delegation route: `spawnTeammate()` requests no per-child `agentOptions`, so an image-bearing first prompt or peer message can only reach a teammate whose inherited route accepts images; choosing a different model for one teammate is a separate model-selection feature. The gates follow `imageInputSupport`'s permissive `'undeclared'` policy: they refuse only a declared modality list that omits `image`, the same condition under which `LlmRuntime` projects images to placeholder text, so a route whose catalog entry discloses no modalities, or declares `image` for a model that cannot read it, is sent the image unchanged and only its provider can reject it. ACP and the DSH SDK provider refuse every image-bearing one-shot prompt until each carries image bytes across its process boundary; Claude Code and Codex refuse because each maps the task to a text-only CLI prompt. A queued image that its teammate target's route refuses at delivery — a hand-appended `team/message/queued` record, or one queued before that route's catalog entry changed — can still head-of-line block delivery to that teammate.

Every Team gate checks the route before its durable append, and the Team transaction does not repeat that check, which awaits a model-info read. The Lead's route has two consumers, and each reads it only after the awaited append: delivery to a Lead target through `root.steer()` applies no further check, and a spawn's `startContinuable` creation check reads and checks it again after the `provisioning` record. The Lead's route changes when the Lead logs a request on a different model. A change to a text-only model between the Team check and the consumer's read is the worse failure direction, because it is a false acceptance: the mailbox still queues the image, the Lead steer applies no delivery-time gate, and the image silently degrades to placeholder text in the Lead's model view. A spawn whose inherited route changes the same way passes the Team preflight, is refused by that creation check, and settles a durable `failed` member, using up the name and a member slot that a preflight refusal leaves available. A synchronous comparison of the Lead's route inside the transaction would narrow only the check-to-append span, since both consumers read the route after the awaited append, so it would change neither failure direction. A change toward an image-capable model only produces a refusal the caller can retry. The `agent-team` README records this window under Known Limitations.

The mailbox's Lead-as-target gate and `SubagentContinuationManager.sendToParent` both resolve the route from `parentAgentOptionsForDelegation`, the Lead's (or parent's) last *logged* request route, not from a model switch that is still pending when the gate runs. A pending switch to an image-capable model can still refuse a teammate's image to the Lead until the Lead's next request logs the new route; a pending switch to a text-only model admits the image, and the runtime then projects it to placeholder text on the Lead's next turn. The `agent-team` README records this under Known Limitations; closing it requires reading the Lead's in-flight route selection ahead of its own request.

## Testing

Unit specs cover the shared gate (`packages/subagent/subagent/tests/image-capability.spec.ts`), the continuable-creation and parent-direction gates plus the child-route probe's live/cold/fallback sources (`packages/subagent/subagent/tests/continuation.spec.ts`), the one-shot `start()` transport check (`packages/subagent/subagent/tests/service.spec.ts`), the shared in-process driver's route check and its ordering against the synchronous delegated-policy capture (`packages/subagent/subagent-in-process-driver/tests/inheritance.spec.ts`), the Team mailbox and spawn gates plus `offloaded` stripping for both mailbox delivery and the spawn prompt (`packages/experimental/agent-team/tests/team.spec.ts`), the widened projection schema (`packages/experimental/agent-team/tests/projection-events.spec.ts`), and the admission/route helpers in isolation (`packages/experimental/agent-team/tests/image-content.spec.ts`). `startContinuable`'s creation gate, the child-route probe, and `sendToParent` each have a spec that gives the child (or, for the Lead target and `sendToParent`, the live parent via a spied `requestHeader()`) an explicit route distinct from the parent's creation options, so a gate or probe that read the wrong Agent's options fails the assertion instead of coincidentally matching; the Team spawn preflight has the same spied-`requestHeader()` coverage. Dedicated specs pin the ownership hold preceding the pending image-capability read in `startContinuable`, a continuable fork child's seed captured before that read (a parent turn completed while it is pending stays out of the child), a caller-signal abort landing while the route read is pending in `sendToParent`, in the mailbox's target check, and in the spawn preflight, the self-message check and the name/member-limit snapshot check each preceding their image check in the mailbox and spawn preflights, `resolveChildRoute`'s per-source fallback for a cold descriptor and a live Activation that each name only a provider, and its `NOT_RESUMABLE` wrap of an `observeSession` failure. In `subagent-in-process-driver`, one spec holds the route check's `resolveModelInfo` promise unresolved while switching the parent's sandbox mode, then confirms the published child still carries the sandbox value captured before that await, not the later one; a second spec confirms a route refusal leaves no entry in `ctx.agents.list()`. Every `SubagentProvider` implementation and stub in the repository pins `imageInput` beside `inheritsParentContext`.
